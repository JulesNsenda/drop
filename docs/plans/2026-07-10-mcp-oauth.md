# Plan: OAuth 2.1 for the hosted MCP endpoint (PRD-041)

## Goal

Make DROP a first-class claude.ai (web) MCP connector: a user clicks "connect",
signs into their DROP box, consents, and claude.ai gets tokens — no API-key
pasting, no Caddy shim. OAuth 2.1 authorization-code + PKCE + dynamic client
registration, riding the existing user/password/MFA + JWT machinery.

## Approach (revised after adversarial review — lean v1)

Three reviewers (OAuth-security, integration/blast-radius, simplicity — the last
grounded in Anthropic's connector docs) reshaped the original plan. The design
below is the reconciled result; the "Agent critiques" section records why.

### Registration — STATIC client, no DCR
claude.ai supports a **pre-registered `client_id`** pasted into the connector's
Advanced settings (Anthropic recommends this *over* DCR). So there is no
`/register`, no client store, no cap/prune. DROP mints **one** public
`client_id` (admin, via a small endpoint/CLI, persisted in the credentials
store) and the operator pastes it into claude.ai. Its `redirect_uri` is the
**fixed constant** `https://claude.ai/api/mcp/auth_callback` — validated by raw
string equality against that allowlisted value. Cutting DCR removes the largest
attack surface and two security blockers (client-name spoofing on the consent
page, registration-flood eviction).

### Token & identity model — SEPARATE key, audience-bound, /mcp-only
**RFC 8707 (Resource Indicators) is a MUST for MCP clients** — claude.ai always
sends a `resource` parameter (the canonical `/mcp` URL, lowercased, no trailing
slash/fragment/default-port) on `/authorize` and `/token`, and the AS **must**
bind it into the token's `aud` claim and exact-match it on each `/mcp` request.
So audience binding isn't optional hardening — it's the spec, and it *is* the
scoping the security review demanded.
- **OAuth access tokens** are JWTs signed with a **dedicated `oauthTokenSecret`**
  (auto-generated beside `jwtSecret`/`mfaChallengeSecret` — the pattern the
  codebase already uses for MFA), carrying **`aud` = the validated `resource`**
  (the `/mcp` URL) and a 15 min TTL. **Three gates** keep them off the rest of
  the API: (a) `/authorize`/`/token` reject a `resource` that doesn't match the
  configured `/mcp` URL (`invalid_target`); (b) the general `authMiddleware`
  **rejects** any token carrying an `aud` claim (session JWTs have none) —
  testable under the jose mock; (c) they verify against a secret the general
  path doesn't hold — real crypto isolation. Only a dedicated `mcpAuthMiddleware`
  on `/mcp` accepts them (verifying `aud` exact-matches the `/mcp` URL, then
  falling back to the existing session-JWT/API-key path), building the same
  `AuthContext` so tool-level `canAccess` is unchanged. This closes the blocker
  where an MCP token could otherwise hit `/secrets`, `DELETE /apps/:name`, or
  `/admin/*` via raw REST.
- **Refresh tokens** (Shape B): opaque, **hashed at rest** (existing scrypt/
  sha256 pattern), stored in the **existing credentials store** (a
  `refreshTokens: []` array — no new `oauth.json`), **rotated on every use**.
  Reuse-detection/chain-revocation is a documented fast-follow.
- **Authorization codes**: opaque (`crypto.randomBytes`), single-use, 60 s TTL,
  bound to `{userId, client_id, redirect_uri, code_challenge}`. In-memory Map,
  **lazily pruned on mint/consume** (no `setInterval` — avoids the Jest
  open-handle leak), **consumed synchronously** (delete-before-validate, no
  `await` between lookup and delete) so a replay can't race the exchange.

### Consent flow — redirect to the SPA (no server-rendered login)
A top-level nav from claude.ai lands on **DROP's own origin**, where the SPA can
read its own first-party localStorage JWT. So:
- `GET /api/v1/oauth/authorize` validates `client_id` (the one static value),
  `redirect_uri` (raw-equals the allowlisted claude.ai callback),
  `response_type=code`, and **requires** `code_challenge` +
  `code_challenge_method=S256` (missing → `invalid_request`; PKCE is mandatory,
  no downgrade). Invalid `client_id`/`redirect_uri` → **error page, never
  redirect** (open-redirector guard). Everything else → `302` to
  `redirect_uri?error=…&state=…`. On success → `302` to a **dashboard SPA
  consent route** carrying the (validated) OAuth params in the query.
- The SPA loads; if the operator already has a dashboard session it's one click,
  else the **existing** login+MFA flow runs (no re-implementation, no
  server-rendered form, no bespoke CSRF token). On **Approve**, the SPA
  `POST`s `/api/v1/oauth/approve` with `Authorization: Bearer <its JWT>` + the
  OAuth params. That call is bearer-authenticated (so `userId` comes straight
  from the session — inherently CSRF-resistant), mints the code, and returns
  `redirect_uri?code=…&state=…`; the SPA navigates there.

### Token endpoint — form-urlencoded
- `POST /api/v1/oauth/token` parses **`application/x-www-form-urlencoded`** (not
  JSON — claude.ai sends form-encoded; JSON-only would 415).
  `grant_type=authorization_code`: consume code, verify `client_id` +
  `redirect_uri` match and PKCE (`base64url(SHA256(verifier)) === challenge`,
  compared with `timingSafeEqual` after a length check; `code_verifier`
  length/charset validated per RFC 7636), issue access + refresh.
  `grant_type=refresh_token`: hashed lookup, **rotate**, issue new pair.

### Discovery & 401
- claude.ai probes **resource-scoped first, then global**: it tries
  `/.well-known/oauth-protected-resource/<mcp-path>` (and the newer
  `/.well-known/protected-resource/<mcp-path>`), falls back to the root
  `/.well-known/oauth-protected-resource`, then the AS metadata. Serve the
  root protected-resource doc **and** the resource-scoped path for the `/mcp`
  route so discovery can't 404 out (a known breakage class — cf. connector
  issue #313).
- Root (spec-mandated location, security headers already apply globally):
  `/.well-known/oauth-protected-resource` (RFC 9728) → `{ resource,
  authorization_servers:[issuer] }`; `/.well-known/oauth-authorization-server`
  (RFC 8414) → issuer + endpoint URLs, `response_types_supported:['code']`,
  `grant_types_supported:['authorization_code','refresh_token']`,
  `code_challenge_methods_supported:['S256']`,
  `token_endpoint_auth_methods_supported:['none']`,
  `scopes_supported` including `offline_access` (refresh opt-in). **No
  `registration_endpoint`** (DCR cut).
- `/mcp`'s 401 (only there — not every API 401) gains
  `WWW-Authenticate: Bearer resource_metadata="<issuer>/.well-known/oauth-protected-resource"`.

### Issuer URL — config-only, fail closed
Issuer/endpoint URLs come **only** from `DROP_PUBLIC_URL` (read directly in
`getPublicUrl()`, mirroring `getDomainSuffix()` — no half-plumbed platform
chain). If unset, every OAuth endpoint and the `/mcp` `WWW-Authenticate`
**fail closed** with "OAuth not configured" — never derived from the `Host`
header or the per-app `domainSuffix` (which is the *apps'* wildcard, not the
API's own address). No separate Host-rejection needed (issuer is never
Host-derived), which also keeps the real-server test simple.

### Auth-enabled only; audited
OAuth endpoints require platform auth enabled (else `authenticateUser` throws —
return a clear "OAuth requires authentication enabled" instead of a 500).
`/authorize`, `/token`, `/approve` mount under `/api/v1/oauth/*` so the existing
`auditMiddleware` (`/api/*`) logs grants and token issuance, and they get a
rate-limit bucket. `/approve` additionally gets `authMiddleware('user')`.

## File-level changes

**New**
- `src/api/oauth/pkce.ts` — S256 verify (base64url, `timingSafeEqual`, verifier
  length/charset).
- `src/api/oauth/authorization-code.ts` — in-memory code store (mint / sync
  consume / lazy prune).
- `src/api/oauth/metadata.ts` — issuer from `DROP_PUBLIC_URL` (fail-closed) +
  the two metadata documents.
- `src/api/routes/oauth.ts` — `/authorize` (GET), `/approve` (POST, bearer),
  `/token` (POST, form-urlencoded), plus an admin `client_id` mint + a minimal
  refresh-token revoke.
- `src/dashboard/src/pages/OAuthConsent.tsx` (+ route) — the Approve/Deny panel.
- Tests: `pkce.test.ts`, `oauth.flow.test.ts` (authorize→approve→token→refresh,
  plus redirect_uri / PKCE-downgrade / oauth-token-rejected-off-/mcp cases),
  `oauth.metadata.test.ts`, and a real-server leg asserting a minted token works
  on `/mcp` (harness sets `DROP_PUBLIC_URL` to its bind address).

**Edited**
- `src/api/middleware/auth.ts` — `oauthTokenSecret` in `CredentialsStore`
  (auto-gen) + `refreshTokens` array; `mintOAuthAccessToken(user)` /
  verify-with-oauth-key helpers; general `authMiddleware` **rejects**
  `token_use:'oauth_access'`; `authMethod:'oauth'` for audit.
- `src/api/mcp/` (or middleware) — `mcpAuthMiddleware` accepting session
  JWT / API key / oauth_access token, replacing the plain `authMiddleware('user')`
  on `/mcp`; add the scoped `WWW-Authenticate` on its 401.
- `src/api/server.ts` — mount `/.well-known/*` at root and the `/api/v1/oauth/*`
  router; rate-limit + auth-enabled guard.
- `src/api/runtime-config.ts` — `getPublicUrl()` (reads `DROP_PUBLIC_URL`).
- `docs/AGENT-DEPLOY.md` — replace the interim §2/§3 workarounds with the
  connector flow; note `static_headers` as the possibly-simpler alternative;
  mark the Caddy shim deprecated.

## Risks & open questions
- **`static_headers` may moot this** on Team+/enterprise claude.ai tiers (a
  fixed-header auth type in beta). Personal-plan operators likely still need
  OAuth. Documented as the "you may not need this" alternative; build proceeds
  because it's the tier-independent path the user chose.
- **No-refresh tolerance unconfirmed**: Shape A (no refresh) hinges on claude.ai
  re-authing gracefully — unverified against a live connector, so we ship
  Shape B (refresh + rotation), the known-good default.
- **Access-token revocation latency**: rotating/revoking a refresh token doesn't
  kill a live 15 min access token; rotating `oauthTokenSecret` kills all MCP
  tokens at once. Acceptable; documented.
- **jose mock can't prove crypto key isolation** (it ignores the secret) — hence
  the *claim*-based gate (`token_use`) as the testable guarantee, with the
  separate key as defense-in-depth verified by code review.
- **CSP `form-action 'self'`**: no longer on the critical path (the cross-origin
  hop to claude.ai is a JS navigation after the bearer `/approve`, not a form
  submit), so no per-route CSP surgery needed.

## Agent critiques considered

- **Security (OAuth):** Blocker — OAuth tokens were unscoped session JWTs
  reaching `/secrets`/`/admin`/`DELETE apps`, defeating the MCP tool boundary →
  **adopted** separate key + `token_use` rejection in general auth + `/mcp`-only
  acceptance. Blocker — unthrottled `/authorize` password oracle → **dissolved**
  by the SPA-redirect (login runs through the already-rate-limited SPA flow),
  plus a rate bucket on the OAuth routes. Blocker — unescaped DCR client name on
  the password page → **dissolved** (DCR cut). Blocker — issuer fallback from
  the wrong domain → **adopted** fail-closed, config-only. Should-fixes adopted:
  mandatory PKCE, sync code consume, raw-string redirect_uri + fixed allowlist,
  refresh rotation (reuse-detection deferred), `timingSafeEqual`, jose-mock
  suffix bug noted, `mustChangePassword` handled by the SPA login path.
- **Integration/blast-radius:** confirmed the token over-grant independently;
  caught that `authenticateUser` returns a token not a `userId` (→ **dissolved**
  by SPA `/approve` reading `userId` from the bearer session); store-init
  omission (→ **dissolved**, no new store); half-plumbed `publicUrl` (→ adopted
  direct `process.env` read); `setInterval` Jest leak (→ lazy prune); audit-log
  gap (→ mount under `/api/v1/oauth/*`); auth-disabled 500 (→ guard);
  Host-rejection breaks the real-server test (→ dropped Host-rejection, issuer is
  config-only anyway); scope `WWW-Authenticate` to `/mcp` (→ adopted).
  Validated: root mounting doesn't collide, CORS default is correct, the flow
  test needs no node-server adapter (only the `/mcp` leg does).
- **Simplicity (doc-grounded):** cut DCR (static client_id), cut the `oauth.json`
  store (fold into credentials store), cut the server-rendered login/MFA/CSRF
  page (SPA redirect), separate signing key over shared-secret-plus-claim, keep
  both tiny metadata docs, default refresh to Shape B — **all adopted**. Flagged
  the `/token` form-urlencoded requirement and the fixed claude.ai redirect_uri —
  **adopted**. Flagged `static_headers` as a possible moot — **documented**.
